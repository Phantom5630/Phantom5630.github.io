    MY CONTRIBUTIONS

    Modular Tower Behavior System

    Tower Data Structure

    Burst Multi-shot Demo

    Pierce Explosive Shot Demo

    • The system is designed to allow easier customization by having each Tower Behavior, Projectile Behavior and Hit Effect as puzzle pieces instead of having lots of prefab variants.
    • There is only a base Tower, Projectile and HitEffect prefab in the project. After assigning and initializing Tower Data, each of them will behave based on the behavior in the data and their own upgrade level.
    • Complete attack pattern evolution of a tower is also supported by current system. (e.g. level 1 = firing limited projectiles, level 2 = burning all enemies in range)
    • Potential future plan: look into Custom Property Drawer for better improvements.

    Spline-based Path Generation

    Visual and Collision Auto Follow Spline

    • Achieved by setting LineRenderer's and PolygonCollider's points based on the data from Spline.
    • The Spline's data is also used directly for enemy movement.

    Event-driven UI with Automated Creation

    Tower Buttons Creation

    Affordability Indicator Demo

    Level Buttons Creation

    • All cost-related UIs are subscribed to System.Action<int> onGoldChanged from the Gold Manager when they are created, instead of constantly checking the current gold in Update to indicate whether player can afford them whenever the current gold value is changed.
    • UI buttons will be created at the beginning of required scene based on each tower and level stored in respective arrays.
    • Currently both types of button has fixed anchored position based on index.
    • For level buttons, the page switching buttons will be activated once the total number of level registered is more than max level per page.
    • Potential future plan: allow tower selection.

    Tower Targeting Priority

    Tower Targeting Priority

    Priority Changing Code

    • Targeting Priority is represented as Enum stored in each Tower and be consumed by TowerBehavior when choosing target.
    • Currently, it is intended that tower will be targeting the same target (if exist) when its priority is changed.
    • When handling towers that always take action without aiming, there will be no priority and the switching options is hidden.
